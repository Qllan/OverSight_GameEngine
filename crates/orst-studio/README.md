# ORST Studio

Редактор ORST Game Engine: сцены, инспектор, игра в окне редактора и скрипты на C# или C++, как в Unity.

## Запуск

```
dotnet build -c Release bindings/csharp/Scripting
cargo run --release -p orst-studio -- path/to/MyGame
```

Без пути открывается стартовый экран: новый проект или один из недавних. Для скриптов на C# нужен .NET 8 SDK, для скриптов на C++ — CMake и компилятор C++ (на Windows — Visual Studio с C++). Без них редактор работает, но скрипты не собираются, о чём пишет Console.

## Проект

```
MyGame/
  project.orst   имя, версия движка, язык, первая сцена
  Assets/        картинки, сцены, скрипты, у каждого файла .meta
  Library/       то, что редактор может пересобрать; не для git
```

Новый проект сразу получает `Assets/Scripts/PlayerMove.cs` (или `.cpp`): ходьба стрелками или WASD.

## Скрипты на C#

Скрипт — класс от `Behaviour`. Его публичные поля (числа, bool, `Vec2`, `Color`, `Rect`, `Entity`, перечисления) становятся компонентом с именем класса: инспектор их показывает, сцена сохраняет, а начальные значения полей служат значениями по умолчанию.

```csharp
using ORST;

public class Spin : Behaviour
{
    [Range(0, 10)] public float Speed = 2;

    public override void Update(float dt) => Transform.Rotation += Speed * dt;
}
```

- `Start()` вызывается перед первым `Update` каждой сущности, `Update(dt)` — каждый тик (60 в секунду) до того, как движок двигает сущности.
- `OnContactBegin(other, contact)` и `OnContactEnd` сообщают о касаниях коллайдеров; `contact.Trigger` говорит, был ли это триггер.
- `GetBehaviour<T>(entity)` даёт скрипт на сущности, `FindBehaviour<T>()` — скрипт, который в игре один (счёт, уровень). `Destroy(entity)` убирает сущность.
- `Engine` — весь движок: клавиши (`Engine.Axis`, `Engine.KeyPressed`), компоненты (`Engine.Get<Velocity>(Entity)`), запросы и остальное из привязки C#.
- `Log`, `Warn`, `Error` и `Console.WriteLine` пишут в окно Console.

Кнопка **New C# script** в окне Project создаёт скрипт по шаблону и открывает его в редакторе кода. Двойной клик по `.cs` тоже открывает его. Редактор сам собирает скрипты при каждом сохранении файла (`Library/Scripts/Scripts.csproj`; его можно открыть в IDE для подсказок). Ошибки компилятора идут в Console, а удачная сборка подменяет старую на месте, сохраняя значения полей по именам. Во время игры новая сборка ждёт Stop.

## Скрипты на C++

То же самое на C++. Скрипт — класс от `orst::Behaviour` и строка `ORST_BEHAVIOUR`. Поля, перечисленные в статической функции `fields`, становятся компонентом с именем класса.

```cpp
#include "orst_script.hpp"

using namespace orst;

struct Spin : Behaviour {
    float speed = 2;

    static void fields(Fields<Spin> &f) { f("Speed", &Spin::speed).range(0, 10); }

    void update(float dt) override { transform().rotation += speed * dt; }
};
ORST_BEHAVIOUR(Spin);
```

- `start()`, `update(dt)`, `on_contact_begin(other, contact)` и `on_contact_end` вызываются так же, как в C#.
- `get_behaviour<T>(entity)`, `find_behaviour<T>()`, `destroy(entity)`, `log`, `warn`, `error`.
- `engine()` — весь движок из `orst.hpp`, `transform()` — Transform сущности.

Редактор собирает все `.cpp` из Assets через CMake в одну библиотеку (`Library/Scripts/CMakeLists.txt`; файл `Library/Scripts/cmake/compile_commands.json` даёт подсказки в редакторе кода) и подгружает её на место старой. Исключение в скрипте попадает в Console и не роняет редактор, но падение внутри C++ кода (например, обращение по нулевому указателю) закрывает редактор, так что сохраняйте сцену перед Play.

## Тайлмапы

Карты хранятся в формате Tiled (`.tmj`), так что их можно открывать и в [Tiled](https://www.mapeditor.org). Кнопка **New tilemap** в окне Project делает новую карту из картинки с тайлами и ставит её в сцену. Готовую карту `.tmj` можно просто перетащить из окна Project в сцену.

Когда выбрана сущность с картой, внизу инспектора появляется раздел Tiles: палитра тайлов, выбор слоя, **Paint** (клавиша B) и **Erase**. Тайлы рисуются левой кнопкой мыши в окне Scene, а Ctrl+Z отменяет весь мазок целиком. При сохранении сцены тайлы записываются в файл карты, и всё остальное в этом файле (объекты, свойства, внешние тайлсеты) остаётся как было.

Карта всегда начинается в начале координат мира: там же её видят столкновения (поле `tilemap` у Body), поиск пути и тени, поэтому Transform её не двигает.

## Игра в редакторе

Play (Ctrl+P) запускает сцену в окне Game: скрипты, движение, физику, анимации и частицы. Клавиатура и мышь окна Game идут в игру. Pause и Step останавливают время и делают один тик. Stop возвращает сцену ровно к моменту Play, так что всё, что игра поменяла, пропадает.

## Сборка игры

**File → Build game...** собирает игру в папку (по умолчанию `Build` внутри проекта):

```
Build/
  MyGame.exe     игра
  Scripting/     хост скриптов C# (для игр на C#)
  Data/          сцены, картинки и собранные скрипты, без исходников
  log.txt        что писали скрипты при последнем запуске
```

Папку можно отдать другу целиком. Игра начинает с первой сохранённой сцены, рисует в 1280×720 и растягивает картинку под окно. Несохранённые изменения в игру не попадают, о чём предупреждает Console. Для игры на C# на компьютере нужен .NET 8 Runtime; игре на C++ больше ничего не нужно.

## Пример

`samples/studio/Coins` — первая игра, собранная в редакторе: соберите все восемь монет и не попадитесь вертушкам. Откройте папку в ORST Studio и нажмите Play.
