# OverSight 2D

Игровой рантайм для 2D-игр на C++ и C#. Движок написан на Rust и собирается в `oversight.dll`. Игра — обычная программа со своим циклом, как в raylib или MonoGame:

```cpp
#include "oversight.hpp"

int main() {
    ov::Engine engine({"Моя игра", 320, 180, 4.0f});
    while (engine.poll()) {
        float dt = engine.dt();
        engine.begin_frame(ov::Color::Black);
        // логика и отрисовка
        engine.end_frame();
    }
}
```

```csharp
using OverSight;

using var engine = new Engine(new Config("Моя игра", 320, 180, 4f));
while (engine.Poll())
{
    float dt = engine.Dt;
    engine.BeginFrame(Color.Black);
    // логика и отрисовка
    engine.EndFrame();
}
```

Поддерживает вид сверху, вид сбоку (платформер) и изометрию.

## Что умеет

- **GPU-рендер.** Окно рисуется видеокартой через wgpu: DirectX 12 или Vulkan на Windows, Vulkan на Linux, Metal на macOS. Если видеокарты нет или драйвер не поднялся, движок сам переходит на программный рендер, а `ov_last_error` объясняет почему. Выбрать явно: `Config.renderer` (`Auto`, `Software`, `Gpu`); примеры понимают ключи `--gpu` и `--software`. Какой рендер работает, видно в панели F3 и в `renderer_name()`. Оба рендера рисуют одинаково: тесты сравнивают кадры попиксельно.
- **Рисование.** Спрайты: область текстуры, поворот, масштаб, отражение, оттенок, прозрачность. Прямоугольники, линии, круги, текст. Встроенный шрифт DejaVu Sans с кириллицей. Слои и глубина: если передать `y` как глубину, получится y-сортировка. Камера с зумом и поворотом. Невидимое не рисуется.
- **Окно.** Логическое разрешение растягивается на окно с чёрными полосами. Есть масштаб только в целое число раз для пиксель-арта и полноэкранный режим.
- **Ввод.** Клавиатура по физическим клавишам (WASD работает на любой раскладке), мышь в координатах экрана и мира, колесо, ввод текста.
- **Геймпады.** До четырёх, каждый в своём слоте 0..3 до отключения. Xbox, PlayStation и другие через XInput и Windows.Gaming.Input. Кнопки названы по месту: `South` — это A на Xbox и крест на PlayStation. Стики от -1 до 1 (вверх — минус, как у `W`), курки от 0 до 1, круглая мёртвая зона 0.15.
- **Анимации.** Нарезка спрайт-листов, анимации по кругу, один раз или туда-обратно.
- **Тайлмапы.** Ортогональные и изометрические, загрузка из [Tiled](https://www.mapeditor.org) (`.tmj`). Слои тайлов, объекты (спавны, триггеры), свойства. Пересчёт координат тайл ↔ мир ↔ экран.
- **Коллизии.** `move_box` двигает прямоугольник по карте со скольжением вдоль стен и возвращает флаги касания: пол, потолок, стены. Тайлы со свойством `solid` непроходимы. Тайлы со свойством `platform` — односторонние платформы. Есть raycast, проверка точки и прямоугольника.
- **Звук.** Эффекты с громкостью и высотой тона, музыка с повтором. Форматы WAV, OGG, MP3.
- **Твины.** 22 кривые плавности (Quad, Cubic, Sine, Expo, Back, Elastic, Bounce с вариантами In, Out, InOut), задержка, повтор и туда-обратно. В C++ `ov::Tween<float>`, `ov::Tween<ov::Vec2>`, `ov::Tween<ov::Color>`, в C# `FloatTween`, `Vec2Tween`, `ColorTween`.
- **Частицы.** Эмиттер выпускает частицы потоком или вспышкой: время жизни, скорость, конус направлений, гравитация, сопротивление, размер и цвет от рождения к смерти, вращение. Частицы — круглые точки или текстура. С одним и тем же `seed` получаются одинаковые частицы. В примере платформера — пыль из-под ног.
- **Горячая перезагрузка.** `set_hot_reload(true)`: сохраните картинку в редакторе или карту в Tiled, и запущенная игра подхватит её за полсекунды. Id текстур и карт не меняются, поэтому код игры ничего не замечает. `reloaded()` подскажет, что карту стоит перечитать (например, объекты). Пример `topdown` так и делает.
- **Действия ввода.** Игра спрашивает «прыжок», а не пробел: `action("jump")`, `bind(jump, Binding::key(Key::Space))`, `action_pressed(jump)`. На одно действие можно повесить клавиши, кнопки мыши, кнопки геймпада и направления стиков; две клавиши на одном действии дают одно нажатие. Меню переназначения ждёт `captured_binding()` — первое, что игрок нажал, — и ставит его через `set_binding`. Привязки сохраняются в короткий текст, который игрок может поправить руками: `jump = key:Space pad:South`.
- **Сущности и компоненты (ECS).** Сущность — это id, компонент — простая структура без указателей (`struct Pos { float x, y; }`). Методы: `spawn`, `set`, `get` (меняет на месте), `remove`, `despawn`. Запросы: `query<Pos, Vel>()` и `each<Pos, Vel>(...)` в C++, `Query<Pos, Vel>()` и `ForEach(...)` в C#. В C++ компонент нужно назвать: `OV_COMPONENT(Pos)`; в C# имя берётся из названия структуры. Мир — это чистые данные, поэтому его можно копировать байт в байт: на этом будут построены сохранения, откат и сеть. Одни и те же вызовы дают одни и те же id и одинаковый порядок обхода на любом компьютере.
- **Встроенные компоненты.** `Transform` (позиция, поворот, масштаб), `Velocity` (скорость), `SpriteRenderer` (спрайт) и `Body` (коробка, которая сталкивается с картой). `update_motion(dt)` двигает всё, у чего есть скорость; тела скользят вдоль стен, скорость гасится об пол и стены, а `contacts` говорит, на чём тело стоит. `draw_entities()` рисует спрайты всех сущностей. Свои компоненты живут рядом с ними в том же мире.
- **Формы столкновений.** Компонент `Collider`: прямоугольник, круг или выпуклый многоугольник (`create_polygon`). Форма двигается, поворачивается и масштабируется вместе с `Transform`. `overlap(a, b)` говорит, пересекаются ли две сущности и куда их развести (нормаль и глубина). `debug_colliders()` обводит все формы в отладочном оверлее F3.
- **Столкновения сущностей.** `update_collisions()` раз в тик находит все пересечения коллайдеров. Сетка соседей ищет пары только рядом, поэтому тысячи пуль и врагов не проверяют друг друга попарно. Слои и маски решают, кто с кем сталкивается: пули бьют врагов, но не друг друга. Триггер только сообщает о пересечении, твёрдый коллайдер со скоростью выталкивается из стен и других тел. `contacts()` даёт пары с состоянием «началось», «продолжается» и «закончилось». Есть поиск сущностей в точке, прямоугольнике и круге и луч по коллайдерам.
- **Поиск пути.** `map.find_path(from, to)` ищет дорогу по карте в обход стен (A*) и возвращает центры клеток. Шаг по диагонали не срезает угол стены. Числовое свойство `cost` на тайле или слое делает клетку медленнее: болото с `cost = 3` враги обойдут, если обход короче трёх клеток. Одинаковые запросы дают одинаковый путь на любом компьютере.
- **Физика тел.** Компонент `RigidBody` вместе с `Collider` даёт сущности массу: динамические тела падают, толкаются и отскакивают, неподвижные служат стенами, кинематические двигает сама игра (платформы, двери). Считает Rapier в детерминированном режиме, `physics_step(dt)` раз в тик. Игра управляет телами через обычные `Transform` и `Velocity`, есть импульсы и силы. Соединения: шарнир (`joint_pin`), склейка (`joint_weld`), верёвка (`joint_rope`) и пружина (`joint_spring`). Состояние физики входит в снимки, поэтому восстановленная игра идёт дальше бит в бит. Гравитация по умолчанию выключена (вид сверху), для платформера: `set_gravity({0, 900})`.
- **Рисование в текстуру и постэффекты.** `create_target(w, h)` даёт текстуру, в которую можно рисовать: `draw_to(target)`, потом `draw_to_screen()`, а готовую текстуру рисуют как обычную (мини-карта, зеркало, слои). Цель без очистки хранит прошлую картинку, на ней удобно рисовать следы и краску. У каждой цели и у экрана своя цепочка эффектов: свечение, размытие, цветокоррекция и CRT (строки развёртки, изгиб, виньетка, расхождение цветов). Оба рендера считают их одинаково. Свои шейдеры пишутся на WGSL (`create_shader`) и работают только на видеокарте. `shake(сила, время)` трясёт мир на экране, а интерфейс остаётся на месте.
- **2D свет и тени.** Эффект `lighting` на экране или на цели освещает картинку сущностями с компонентом `Light`: цвет, сила, радиус, высота над землёй и мягкость тени. Тени отбрасывают коллайдеры на теневых слоях (`set_shadow_layers`) и сплошные клетки карт (`set_shadow_tilemap`). Тень начинается за предметом, а его лицевая сторона остаётся освещённой. Карта нормалей (`set_normal_map`, красный вправо, зелёный вверх) даёт спрайту объём: сторона к свету ярче, от света темнее, с учётом поворота и отражения спрайта. Фоновый свет задаётся в самом эффекте. Оба рендера считают свет одинаково.
- **Скелетная анимация.** Свой формат в JSON: кости, слоты с вложениями (участки одного атласа) и анимации с поворотом, сдвигом, масштабом, сменой вложения, цветом и событиями. Ключи бывают линейные, ступенчатые и плавные. Один файл (`load_skeleton`) служит многим скелетам (`create_skeleton`). Смена анимации идёт плавным переходом за `mix` секунд. Кость можно повернуть из кода поверх анимации (`set_bone_override`, например башню к прицелу), а точку на кости взять в мире (`bone_point`, дуло). События (`fired("step")`) дают звук шага и выстрел в нужный кадр. Скелет рисуется обычными спрайтами, поэтому работает с обоими рендерами и со светом.
- **GPU-частицы.** `create_gpu_emitter` берёт тот же конфиг, что и обычный эмиттер, но не двигает частицы каждый кадр: он записывает только их рождение, а видеокарта сама считает, где частица сейчас (полёт с гравитацией и сопротивлением по точной формуле, размер, цвет, вращение). Новые частицы дописываются в буфер на видеокарте кусками, поэтому сотни тысяч искр и дыма почти ничего не стоят процессору. Программный рендер считает по той же формуле, картинки совпадают в тестах. Частицы можно посчитать (`count`), но не прочитать по одной: для этого есть обычный эмиттер.
- **Автоатлас и 100 тысяч спрайтов.** Текстуры до 512×512 сами собираются в общие страницы атласа (отдельно чёткие и сглаженные), поэтому спрайты из разных файлов рисуются одним вызовом видеокарты. Изменённая текстура обновляется на месте, освободившееся место переиспользуется. Каждый спрайт, тайл и символ уходит на видеокарту одной записью (инстансинг), а не шестью вершинами. Пример `cargo run --release --example sprite_bench` меряет кадр из 100 000 спрайтов: на процессоре он занимает около 12 мс.
- **Сцены и переходы.** Сцена — это число, которое выбирает игра: меню, уровень, пауза. `go_scene(LEVEL)` меняет сцену, `push_scene(PAUSE)` кладёт её поверх текущей, `pop_scene()` возвращает к прежней. Смену закрывает затемнение (`Fade`) или шторка (`Wipe`) любого цвета. Сцена меняется в середине перехода, когда экран закрыт, и в этот кадр `scene_entered()` возвращает новую сцену: тут игра и загружает уровень. Пока идёт один переход, второй не начнётся, так что двойной клик по «Играть» не запустит уровень дважды.
- **Снимки состояния.** `snapshot()` возвращает байты мира: сущности, компоненты, генератор случайных чисел и счётчик тиков. `restore(bytes)` продолжает игру ровно с этого места. На этом строятся сохранения, откат для сетевой игры и повторы. `state_hash()` — отпечаток состояния: если две копии игры идут в ногу, отпечатки на каждом тике совпадают, а по расхождению видно, где они разошлись. Текстуры, карты и звуки в снимок не входят: это ресурсы, игра загружает их сама.
- **Фиксированный шаг логики.** Логика игры идёт ровными тиками (60 в секунду, можно сменить): `for (i = 0; i < ticks(); ++i) update(tick_dt())`. Игра ведёт себя одинаково при 30 и 144 FPS, а это нужно для повторов и сетевой игры. `tick_alpha()` подсказывает, насколько сдвинуть рисунок между тиками для плавности.
- **Случайные числа с зерном.** `random_seed`, `random_float`, `random_range`, `random_int`: одно и то же зерно даёт одну и ту же игру на любом компьютере.
- **Отладочный оверлей.** F3 включает панель с FPS, временем кадра, числом отрисовок, камерой и мышью. `debug_rect`, `debug_line`, `debug_circle`, `debug_text` рисуют поверх всего только при включённом оверлее, `debug_tilemap` обводит стены, платформы и объекты карты. Клавишу можно сменить или отключить: `set_debug_key`.

## Сборка под Windows

Нужно поставить:

1. **Rust:** <https://rustup.rs>, установщик `rustup-init.exe`, вариант по умолчанию (MSVC).
2. **Visual Studio 2022** (или Build Tools) с нагрузкой «Разработка классических приложений на C++». В ней есть компилятор и CMake.
3. **.NET 8 SDK** для игр на C#: <https://dotnet.microsoft.com/download/dotnet/8.0>.

Сборка движка, из корня репозитория:

```
cargo build --release -p oversight
```

Получатся `target\release\oversight.dll` и библиотека импорта `target\release\oversight.dll.lib`.

Движок можно не собирать, а скачать готовым: архив `oversight-sdk-<версия>-windows-x64.zip` на странице [Releases](https://github.com/Qllan/OverSight_GameEngine/releases). В нём DLL, `.lib`, заголовки и пакет для CMake (`find_package(oversight)`), а `README.md` внутри объясняет, как подключить. Архивы собирает CI по тегу `oversight-v<версия>`; инструкцию по сборке SDK из исходников см. в `sdk/package.py`.

### Игра на C++

Подключите `bindings/cpp` в свой `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.16)
project(my_game CXX)

add_subdirectory(path/to/OverSight_GameEngine/bindings/cpp oversight)
add_executable(my_game main.cpp)
target_link_libraries(my_game PRIVATE oversight)
target_compile_options(my_game PRIVATE /utf-8)   # исходники в UTF-8
oversight_copy_runtime(my_game)                   # кладёт oversight.dll рядом с exe
```

Собрать (из «Developer PowerShell for VS 2022» или любого терминала с CMake):

```
cmake -S . -B build
cmake --build build --config Release
```

Если DLL лежит не в `target\release`, укажите папку: `cmake -S . -B build -DOVERSIGHT_LIB_DIR=C:/path/to/dll`.

Без CMake: добавьте в проект Visual Studio папку `crates/oversight/include` в пути заголовков, `oversight.dll.lib` в компоновщик, а `oversight.dll` положите рядом с exe. Из C подключайте `oversight.h`, из C++ — `oversight.hpp`.

### Игра на C#

```
dotnet new console -n MyGame
cd MyGame
dotnet add reference path/to/OverSight_GameEngine/bindings/csharp/OverSight/OverSight.csproj
```

Привязка сама копирует `oversight.dll` из `target\release` в папку сборки. Если DLL лежит в другом месте, задайте свойство `OverSightLibDir` в своём `.csproj`.

## Примеры

В `samples/` три игры, каждая на C++ и на C#. Карты лежат в `samples/assets`, их можно открыть в Tiled.

| Пример | Управление | Что показывает |
|---|---|---|
| `topdown` | WASD, стрелки или стик геймпада | ходьба, стены, y-сортировка, табличка с текстом из свойства объекта |
| `platformer` | A/D, Space или геймпад (стик и A) | гравитация, прыжок, односторонние платформы, камера, финишный флаг |
| `isometric` | WASD (шаг по клеткам), мышь | изометрическая карта, сортировка по глубине, клетка под курсором |

C++:

```
cargo build --release -p oversight
cmake -S samples/cpp -B build/samples
cmake --build build/samples --config Release
build\samples\Release\topdown.exe
```

C#:

```
cargo build --release -p oversight
dotnet run --project samples/csharp/TopDown -c Release
```

С ключами `--headless 200 --screenshot shot.png` пример проходит заскриптованный забег без окна и сохраняет последний кадр. Так их запускает CI.

## Карты из Tiled

- Сохраняйте карты в формате JSON (`.tmj`). Тайлсеты можно встраивать в карту или держать отдельными файлами `.tsj`.
- Слои тайлов — в CSV или base64 без сжатия. Режим «Бесконечная карта» нужно выключить.
- У тайлсета должна быть одна картинка (коллекции картинок пока не поддерживаются).
- Свойства тайлов: `solid` (bool) — стена, `platform` (bool) — односторонняя платформа. Эти свойства можно повесить и на весь слой.
- Объекты (точки, прямоугольники) читаются с именем, классом и свойствами: `find_object("player")`, `string(obj, "text")`, `number(obj, "hp")`.

## Тесты

```
cargo test -p oversight                    # тесты движка
cmake -S bindings/cpp -B build/bindings && cmake --build build/bindings --config Release
ctest --test-dir build/bindings -C Release # C и C++
dotnet run --project bindings/csharp/Smoke # C#
```

CI (`.github/workflows/oversight.yml`) прогоняет всё это на Windows, а также запускает шесть примеров без окна и проверяет, что C++ и C# рисуют одинаковые кадры.
